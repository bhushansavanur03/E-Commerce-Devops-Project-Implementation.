# Containerization of Java-Based Microservice

The next step involved containerizing the Java-based microservice using a multi-stage Dockerfile. The application uses Gradle as its build automation tool.

## Stage 1: Build Stage (Builder Image)

This stage is responsible for compiling and packaging the Java application using Gradle.

1. **Use a JDK Base Image**
   - The `eclipse-temurin:21-jdk` image is used as the builder image.
   - It provides the Java Development Kit (JDK) required to compile and build the application.

2. **Set the Working Directory**
   - `WORKDIR /usr/src/app/` establishes the working directory inside the container.
   - All subsequent build operations are performed from this directory.

3. **Copy Essential Gradle Files**
   - The `gradlew`, `settings.gradle`, and `build.gradle` files are copied into the container.
   - The `gradle/` directory is also copied to provide the required Gradle wrapper configuration.

4. **Set Execution Permissions**
   - `chmod +x ./gradlew` grants execution permissions to the Gradle wrapper script.
   - This allows Gradle commands to be executed inside the container.

5. **Download Gradle Dependencies**
   - `./gradlew` initializes the Gradle wrapper and prepares the Gradle environment.
   - `./gradlew downloadRepos` downloads the required repositories and dependencies for the application build.

6. **Copy Application Source Code**
   - The application source code is copied into the container.
   - The `pb/` directory is copied into the container as `proto/`.
   - This directory contains the Protocol Buffer files required during the build process.

7. **Build the Java Application**
   - `./gradlew installDist -PprotoSourceDir=./proto` builds and packages the Java application.
   - The `installDist` task generates an executable application distribution along with its required dependencies.
   - `-PprotoSourceDir=./proto` specifies the location of the Protocol Buffer source files.

## Stage 2: Runtime Stage (Final Image)

This stage creates the final runtime image required to execute the Java microservice.

1. **Use a Minimal JRE Base Image**
   - The `eclipse-temurin:21-jre` image is used as the runtime base image.
   - It provides the Java Runtime Environment (JRE) required to execute the application without including the full JDK and build tools.

2. **Set the Working Directory**
   - `WORKDIR /usr/src/app/` establishes the application working directory inside the runtime container.

3. **Copy the Built Application**
   - The application distribution generated in the builder stage is copied into the final runtime image.
   - This includes the executable scripts and required application dependencies generated by Gradle.

4. **Configure Environment Variables**
   - `AD_PORT=9099` defines the port configuration for the Ad microservice.

5. **Define the Container Entry Point**
   - `ENTRYPOINT ["./build/install/opentelemetry-demo-ad/bin/Ad"]` specifies the executable used to start the application.
   - This launches the Ad microservice inside the container.

## Summary

- Implemented a multi-stage Docker build for the Java-based Ad microservice.
- Used Eclipse Temurin JDK 21 for compiling and packaging the application.
- Used Gradle Wrapper to manage dependencies and build the application.
- Integrated Protocol Buffer files into the build process.
- Used Eclipse Temurin JRE 21 as the runtime environment.
- Copied the generated application distribution into the final image.
- Created an optimized container image containing the required runtime components.
